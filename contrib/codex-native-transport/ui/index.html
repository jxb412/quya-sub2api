Codex Native Transport

与官方 Codex CLI 逐版本一致的网络栈与指纹。养池锁定 292/332 字节的有效票，保持会话缓存亲和。

养池（常用）

锁定 292 或 332 字节的有效票；其它长度不锁、继续试。生产建议使用 pinned 身份策略，保留会员原 session 和 prompt_cache_key。面板访问 http://面板地址/?token=你的token。

养池策略

默认“全部”。取消全部后可单选或多选；只有选中套餐会养池、捕获/注入锁票和到期前预刷新。套餐来自账号 credentials.plan_type，读取不到时按直通处理。限定套餐需填写下面的宿主 admin API 配置。

被动=靠用户请求，上游出现 292/332 有效票就锁进池（默认开）。主动=对已有过真实流量的（账号×型号）、还没锁到有效票的格，后台用最小 hi 补票（走出口池轮换换 IP），锁到即停、TTL 过期再养。均需 turn_state_mode=pin。
休息机制（事件触发 + 优先级排空）：休息不按时间触发。只有当某个号在养池模型上没有任何有效票、且出口池已经整整轮转一圈仍铸不出有效票 时才休息；手里有有效票的号、票过期后一圈内就能重新铸出的号永远不休息。休息 = 通过 admin API 把该号的调度优先级临时改成“排空优先级”：宿主只在分配新会话时看优先级，已粘住的老会话继续留在原号（不打散、提示缓存不丢），闲置满宿主粘性 TTL 自然脱落；期间不探铸。休息到点写回原优先级、重新开始轮转出口池铸票。“最短间隔”只是防抖。连续“转满一圈→休息”达“卡住轮数”的格进入放弃铸票：真实流量退回直通（走账号自己的出口、保留客户端会话身份、不换身份），养池不再探它，“重试间隔”后再给一圈机会。需配 admin API + 开启任一养池 + 出口池非空；建议配 pin 持久化路径（休息集含原优先级落盘，重启/关停都能写回，不会卡在低优先级）。

全池主动养池（内置 admin key·覆盖空闲号）

只有这个列表里的模型参与 pin：铸票出口池、身份轮换、票注入、被动捕获、休息编排、养池、面板。其它模型即使在 pin 模式下也按直通处理（走账号自己出口、保留客户端身份、不建格、不耗额度）。默认 gpt-6-astra + gpt-5.6-sol。
全池养池：插件直接调宿主 admin API 枚举全部可调度 openai oauth 号并取 access_token，对每个（号×模型）没锁真6的格发最小 hi 造票（借任一真实模板做请求形状，出口走下面的代理池）。覆盖从没跑过流量的空闲号。
需 turn_state_mode=pin、admin key 非空、且出口代理池非空。admin key = 全站管理员权限，请用后台可单独吊销的 API key，勿填 JWT。首轮需至少一条真实 codex 流量喂进来做“形状模板”。

智商切换通知（Telegram）

填了 Token + Chat ID 即开启：每当（账号×模型）智商切换（🔴掉智 / 🟢回真6）就直连 api.telegram.org 推一条。即时模式同一格两次通知至少间隔“冷却”秒防抖；批量摘要模式每“窗口”秒把这段时间的变更汇总成一条。文案里账号邮箱以 @ 打码。需服务器能直连 Telegram，发送失败静默、绝不影响转发与养池。

出口代理池（铸票出口）

四种模式互斥，未选模式的配置不会参与请求。第三方代理 API：每次铸票先读取 host:port:user:password 并以 SOCKS5H 出站。云桥随机 IPv6：每次铸票在两台网关间轮转并生成全新随机用户名，以 HTTP 代理分配新的 IPv6 出口；密码只保存在加密插件配置中。两种动态模式只在未锁票或预刷新时工作，并强制“锁定后使用账号原代理”。
静态池：每行独立连接，每格连续达到门槛仍未获得 292/332 才换下一行。
