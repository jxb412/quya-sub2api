# Quya：按分组零新增提示词

实现日期：2026-11-26。

## 使用

管理员在「分组管理 → 新建/编辑 OpenAI 分组」开启「零新增提示词」。默认关闭；普通分组保持原有行为。支持该分组下的 OAuth 和第三方 API Key 账号。

策略取自鉴权后的 API Key 所属分组，在首次转发时固定。同一请求的重试、切换账号与 HTTP/WS 桥接不会重新开启提示词添加。已经建立的 WS 连接保持原策略，需要重连后使用新配置。建议使用新会话验收：开关不会清除客户历史中已经存在的提示词。

## 承诺与边界

- 不添加网关默认 Codex 指令、管理员强制指令模板、Claude Code Todo 提示、Spark 图片限制提示或自动图片桥接提示。
- 不为没有声明图片工具的请求自动启用 Codex 图片桥接；客户明确提交的图片工具继续按原权限和协议校验处理。Images 接口仍保留生成/编辑必需的工具声明，但不补额外自然语言指令。
- 协议兼容转换不再为缺失工具结果添加 `(empty)`，不再为移出的工具图片添加说明文字，不补自定义工具参数的说明或默认工具搜索说明。客户自己发送的同名文本照常保留。
- 客户的 system/developer/instructions 及工具描述继续保留。OAuth 必要时将 system 角色转换为 developer，缺少必需的 instructions 时可补空字符串；不能偷偷回退为默认助手提示词。
- 保留鉴权、风控审核、模型映射、计费、会话恢复、缓存及必要的协议结构转换。因此这不是 JSON 字节透传，也不承诺所有协议的消息位置和封装完全相同。
- Codex 模型目录不再补入本地内嵌的指令模板；上游原来返回的指令模板保留。不会删除客户端或第三方服务自行添加的内容，也无法控制第三方服务器内部的提示词。
- 不将此开关视为绕过内容审核或上游安全策略的开关。

## 数据库与发布

迁移：`backend/migrations/254_group_openai_zero_prompt_injection.sql`。

新增 `groups.openai_zero_prompt_injection BOOLEAN NOT NULL DEFAULT FALSE`，不新增表、不重置数据库、订阅或余额。Ent 模型、管理创建/更新/复制、鉴权查询投影与鉴权缓存均已同步；缓存版本升至 29，旧版本快照不能被新实例当成有效策略快照。

上线时应先在测试环境验证迁移，再部署全部提供服务的实例，最后才开启目标分组。旧二进制不会执行此策略，因此混合版本运行期间不能向客户承诺所有请求均遵守零新增规则。回滚时恢复旧镜像即可兼容保留的新增列，但旧版本不具备本功能，需关闭对该功能的承诺。
